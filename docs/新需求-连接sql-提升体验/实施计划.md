# Assistant 连接 SQL 与体验重构实施计划

> 状态：已按用户批准方案完成首版实现与自动验证（2026-08-12）；数据库账号权限不设硬性门槛，但执行通道强制只读
>
> 需求来源：[新需求-连接sql-提升体验.md](新需求-连接sql-提升体验.md)
>
> 适用仓库：`assistant/` 独立 Git 仓库
>
> 当前基线：`feature/vision-screenshot`，工作区已有未提交修改；实施前必须先保护现有改动

> 实施结果：已完成 AI 自主只读数据库工具、全库目录缓存、Windows 凭据保存、统一智能动作、普通 Word 文档授权续写、当前显示器 OCR、受控逐字代打、手机服务热键、三路状态灯和任务栏分页。2026-08-12 用户进一步取消 `@assistant-db` 人工触发要求：数据库目录随 SQL 请求提供，AI 自主决定是否执行最多两次实时只读查询。真实数据库连接、Navicat/Word/IME/多显示器和任务栏行为仍需在用户 Windows 会话中做交互验收。

## 1. 结论先行

本轮不建议“推翻后一次性重写”，而建议把 Assistant 重构为一条统一、可验证、可取消的辅助链路：

```text
可靠文本上下文（Navicat / Word）
              │
              ├─ 缓存数据库目录 ─→ AI 自主只读工具 ─→ 实时数据库上下文
              │
              └─ 文本读取失败或用户主动覆盖 ─→ 当前屏幕 OCR
                                      │
                                      ▼
                         统一建议状态与上下文校验
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
                任务栏提示          手机完整答案       受控逐字代打
```

核心产品原则：

1. **能读全文时优先使用全文和精确光标。** 不因为新增 OCR 或数据库能力而降低 Navicat、Word 的现有可靠读取能力。
2. **OCR 是用户明确触发的保底，不在后台静默截屏。** 文本读取失败时给出清晰提示；用户也可以主动强制 OCR。
3. **数据库访问由 AI 自主决策，执行路径强制只读。** 每次提供缓存目录，只有上下文确实需要实时事实时才调用工具；账号权限不作为连接门槛，但 Assistant 不向数据库发送写入语句。
4. **“劫持键盘”产品化为“受控逐字代打”。** 默认关闭，仅在答案、窗口、文档和光标都仍然匹配时吞掉合格按键；任何不确定情况都立即停止并放行用户按键。
5. **总开关仍然是唯一最高级开关。** `Ctrl+Alt+S` 关闭后，除总开关外的探测、OCR、数据库、AI、代打、任务栏、手机服务和业务热键全部停止。
6. **一次只存在一个有效上下文。** 文档、光标、连接配置或前台窗口变化后，旧请求、工具调用和旧答案立即失效，迟到结果不得写入 UI 或代打队列。

## 2. 当前能力与需求差距

| 领域 | 当前实际能力 | 本轮差距 |
|---|---|---|
| Navicat | 通过 `WM_GETTEXT` 优先读取完整 SQL，通过状态栏换算精确光标；具备 4096 字符截断保护、自动补全和选区诊断 | 需要数据库目录缓存与 AI 自主只读工具 |
| Word | 通过 Word COM 读取完整正文、精确光标和选区；当前只在快捷键触发后识别 SQL/数据库练习题 | 尚未形成与 Navicat 一致的“全文 + 光标建议”产品入口；普通 Word 内容是否自动发给 AI 需要明确授权策略 |
| OCR | 已能主动截取前台根窗口，发送干净全图和光标局部图给视觉模型 | 不是文本失败时的统一保底；不是当前显示器全屏；无统一的来源降级状态 |
| 键盘 | 低级键盘 Hook 只用于 Navicat 全文读取失败时的内存兜底，不吞键、不写回 | 尚无逐字代打、目标校验、注入事件隔离和失败放行机制 |
| 任务栏 | 无边框、不激活、不进 Alt+Tab，可显示建议；当前工作区正在增加长内容翻页 | 缺少统一状态灯、来源标识和代打/数据库状态 |
| 手机 | 带 token 的局域网页，可显示完整答案并反向同步部分设置 | 手机服务虽可从托盘切换，但无专用默认快捷键和统一运行状态；页面信息层级偏设置导向 |
| 热键 | 总开关、候选、诊断、Word 识题、OCR、任务栏翻页逐步累加 | 功能分散、记忆成本高，缺少“智能动作”统一入口和热键迁移方案 |
| 状态管理 | 主要集中在 `MainWindow.xaml.cs` 中，以多个字段和取消令牌分别维护 | 模式变多后容易产生状态组合爆炸，需要显式状态模型和统一的上下文版本号 |

## 3. 建议的最终产品体验

### 3.1 第一次设置

设置页重组为五个清晰区域：

1. **AI 服务**：DeepSeek、视觉模型、API Key 状态。
2. **内容来源**：Navicat、Word、OCR 的启用方式和隐私说明。
3. **数据库增强**：连接配置、测试连接、活动数据库和数据读取边界。
4. **输出方式**：任务栏、手机、受控逐字代打。
5. **快捷键**：显示核心快捷键，进阶快捷键折叠；保存前检查格式、重复和系统占用。

数据库连接配置包括显示名称、主机、端口、用户名、可选优先数据库、TLS 模式和超时。密码只保存到 Windows 凭据管理器；`settings.json` 只保留非敏感字段和稳定的连接配置 ID。

点击“测试连接”时依次显示：

- 网络是否可达；
- MySQL 版本与当前数据库；
- 当前账号可见的业务库和表数量；
- 跨库目录是否可读取；
- TLS 是否生效；
- 失败时的可操作原因，不显示连接字符串或密码。

### 3.2 Navicat：默认全文续写

普通输入沿用现有可靠链路：读取完整 SQL、精确光标、局部确定性语法保护，再请求 AI。数据库工具启用后，启动或保存设置时读取账号可见的非系统库目录，缓存 15 分钟。每次 SQL 请求提供稳定目录：所有可见库、表/视图、紧凑字段类型、键标记、外键关系和近似规模；不预取业务行。目录到期时当前请求先使用旧快照并在后台刷新，避免目录轮询阻塞补全。

一次自主数据库增强流程为：

1. 捕获文档、光标和连接配置，生成不可变上下文 ID；
2. 提供缓存目录，让模型在 `tool_choice=auto` 下先判断现有元数据是否足够；
3. 只有实时数量、排名、聚合、样例分布、当前状态或缺失精确 Schema 时，模型才调用 `query_mysql_readonly`；
4. 本地验证语句类型、单语句、危险关键字、查询长度和资源上限；
5. 在只读事务中执行；每次补全最多两次工具调用，优先一次聚合查询；
6. 最多读取有限行数和有限字节，将结果标为“不可信数据库数据”后回传工具结果；
7. 模型结合工具结果输出最终 `DisplayText` 和 `InsertText`；工具失败时使用目录降级回答；
8. 每次调用前后及写入 UI 前再次核对文档哈希、光标、连接配置和请求序号。

数据库结果不直接拼入 SQL，不把 AI 生成的任意语句无条件交给服务器。

### 3.3 Word：全文读取，按文档授权 AI

Word 继续使用 COM 读取完整正文、精确光标和选区。建议的隐私与易用性折中是：

- 本地全文捕获可以自动进行；
- 普通 Word 文档首次使用 AI 时，通过智能动作明确开启“当前文档辅助”；
- 授权后，根据完整文档和光标位置自动提供续写，切换文档后重新确认；
- 现有 SQL/数据库练习题识别能力作为 Word 场景的一种结果类型保留，不再需要独立的主流程热键；
- Word 有选区时，智能动作优先分析选区；没有选区时才做光标续写或题目识别；
- 关闭总开关、切换文档或撤销当前文档授权后，立即取消请求并清理保存的题目状态。

这样能满足“完整文件内容 + 光标建议”，同时避免 Assistant 在用户只是打开普通文档时自动外发整篇内容。

### 3.4 OCR：明确的人工保底

OCR 有两种进入方式：

1. **读取失败提示**：全文或光标不可靠时，主流程灯变红或黄色，并提示按 OCR 快捷键；不自动截屏。
2. **用户主动覆盖**：即使全文读取成功，用户认为结果不可信时也可强制 OCR。

建议默认截取“当前光标所在显示器”的完整画面，而不是所有显示器组成的虚拟桌面；设置中可改为“仅前台窗口”以降低隐私暴露。请求仍保留干净图和光标附近标记图：

- 有可靠文本光标时标记光标；
- 只有屏幕内容、没有可靠光标时，可以给出完整答案，但不允许启动逐字代打；
- 图片和 Base64 只在内存中存在，不落盘、不进日志；
- 前台窗口、截图哈希或请求序号变化后，旧 OCR 结果作废。

### 3.5 受控逐字代打

用户打开代打后，每次按下一个“合格普通按键”，Assistant 在当前编辑位置插入 `InsertText` 的下一个文本元素；实际按键字符不进入编辑器。产品行为定义如下：

- 每次启动、总开关恢复、切换应用或得到新答案后均默认关闭，防止意外吞键；
- 只使用 `InsertText`，绝不输入面向人的 `DisplayText` 或解析文字；
- 第一阶段只支持已验证的 Navicat 和 Word 编辑区域，不对任意应用全局代打；
- 只拦截无 `Ctrl`/`Alt`/`Win` 修饰的普通按键；不消耗功能热键、修饰键、自动连发、IME 组合输入和 Assistant 自己注入的事件；
- `Esc` 永远立即关闭代打，并正常消费本次退出动作；
- 以 Unicode 文本元素而不是 UTF-16 单元推进，中文和代理对不会被拆坏；
- 注入前核对前台进程、根窗口、文档身份、原始上下文和预期光标；任意不一致都自动关闭；
- 注入失败或无法确认目标时采用 **fail-open**：不吞用户按键；
- 每插入一段后由正常探测链路确认用户仍在跟随建议，不能只相信本地计数器；
- 答案输完后自动关闭代打，状态灯回灰，并提示“已输入完成”；
- 不使用剪贴板，避免覆盖用户现有剪贴板内容；
- Assistant 设置窗口、密码输入框、UAC/高权限窗口和无法验证的编辑控件一律禁止代打。

现有 `KeyboardFallbackService` 继续只负责“读取失败时恢复用户实际输入”。新建独立的 `GuidedTypingService`，不能把读取兜底和写入代打混在一个 Hook 状态中。

### 3.6 手机与任务栏

任务栏继续是短而即时的通道，手机是完整结果通道：

| 通道 | 主要内容 |
|---|---|
| 任务栏 | 三个状态灯、来源短标签、短建议、候选/分页提示、错误的下一步动作 |
| 手机 | 完整答案、完整续写、解析、候选、来源、生成时间、是否使用数据库/OCR，以及非敏感设置 |

手机快捷键直接启停局域网服务：关闭时停止监听端口并让旧页面明确断开；开启时恢复上次端口和 token。总开关关闭时仍然强制关闭手机服务，但保留用户期望设置，以便再次开启总开关时恢复。

手机页面不展示数据库密码、连接字符串、API Key、数据库原始行或数据库配置编辑入口。数据库返回的数据只用于当次建议，除非后续另行批准“手机展示数据证据”。

## 4. 状态灯方案

建议使用 **三个状态灯**。两个灯不足以同时表达主流程、数据库和代打；四个以上会增加辨认成本。状态灯显示在任务栏提示左侧、主窗口状态区和手机页标题处，并提供文字/Tooltip，不能只靠颜色传达状态。

### 灯 1：主流程

| 颜色 | 含义 |
|---|---|
| 灰 | Assistant 关闭 |
| 蓝 | 已开启，等待受支持的前台内容或内容未变化 |
| 黄 | 正在读取、等待防抖、请求 AI 或执行 OCR |
| 绿 | 当前上下文已有可用答案 |
| 红 | 当前读取、配置、网络、AI 或 OCR 失败 |

### 灯 2：数据库增强

| 颜色 | 含义 |
|---|---|
| 灰 | 当前建议未请求数据库，或数据库增强关闭 |
| 蓝 | 已配置并待命 |
| 黄 | 正在连接、读取 Schema 或执行受限查询 |
| 绿 | 当前答案已使用有效的数据库上下文 |
| 红 | 权限、连接、查询验证或执行失败；本次不使用数据库结果 |

### 灯 3：受控代打

| 颜色 | 含义 |
|---|---|
| 灰 | 关闭 |
| 黄 | 已请求开启，但答案或目标尚不可安全使用 |
| 绿 | 已开启，可逐字输入当前答案 |
| 红 | 因焦点、上下文或注入异常自动停止；短暂显示后回灰 |

手机服务不占用第四个灯，在任务栏文字区使用手机小图标和“开/关/异常”即可，因为它不是当前答案正确性的组成部分。

## 5. 快捷键重新规划

默认突出六个可记忆的核心快捷键：

| 功能 | 建议默认值 | 设计理由 |
|---|---|---|
| Assistant 总开关 | `Ctrl+Alt+S` | 保留现有肌肉记忆与产品最高级开关 |
| 智能分析当前内容 | `Ctrl+Alt+A` | Navicat 有选区则诊断，无选区则强制刷新；Word 识题/续写；读取失败时提示 OCR |
| 完整答案复制到剪贴板 | `Ctrl+Alt+C` | Navicat 生成完整 SQL，Word/OCR 题目生成完整参考答案；只复制，用户自行粘贴 |
| 强制当前屏幕 OCR | `Ctrl+Alt+O` | 用户明确覆盖文本来源，语义直接 |
| 受控逐字代打开关 | `Ctrl+Alt+D` | 对应“代打”，与油猴需求一致 |
| 手机完整答案开关 | `Ctrl+Alt+M` | 对应 Mobile，直接启停手机服务 |

以下能力改为进阶交互，默认不再占用主要字母热键：

- 三候选切换：优先通过任务栏按钮/鼠标滚轮、托盘和手机页面操作；保留可配置的进阶热键，旧用户迁移时可继续使用 `Ctrl+Alt+R`。
- 选区诊断：合并进“智能分析当前内容”，不再单独要求记忆 `Ctrl+Alt+E`。
- Word 识题：合并进“智能分析当前内容”，迁移旧 `Ctrl+Alt+A` 时行为自然延续。
- 任务栏分页：保留当前正在开发的 `Win+PageUp` / `Win+PageDown` 作为进阶固定键，最终是否改为可配置，要在合并现有未提交修改后决定。

快捷键实现必须增加：

- 同一配置内的重复检查；
- 默认用低级键盘 Hook 独占匹配到的业务组合键并吞掉主键事件，避免钉钉等普通应用同时响应；
- Hook 回调只做状态匹配和异步投递，避免处理超时被 Windows 静默卸载；安装失败时降级为普通系统热键，并逐项显示冲突；
- 总开关关闭时独占拦截器只保留 `Ctrl+Alt+S`，其余组合键立即放行；
- 旧设置迁移，不让升级后的用户突然失去已有操作能力；
- 代打开启时先处理所有功能快捷键，再判断是否吞普通按键。
- 完整答案请求与普通续写使用独立取消令牌；复制前复核窗口、文档哈希和光标，剪贴板正文不写日志，且绝不自动执行或粘贴 SQL。

这里的“独占”是 Windows 普通桌面范围内的最佳努力，不等于操作系统级绝对最高优先级：安全桌面、系统保留组合键、权限更高的应用，以及钩子链中行为异常的其他低级 Hook 不在保证范围内。

## 6. 数据库连接与安全边界

### 6.1 凭据处理

- 原需求文件中出现了明文数据库凭据。**开始实现或提交该目录前，必须先更换该密码并从待提交文档中删除明文**；本计划不复制该凭据，也不会在计划阶段尝试连接。
- 数据库密码使用稳定连接配置 ID 保存为 Windows 通用凭据，例如 `Assistant/MySql/{profileId}`。
- `settings.json`、日志、异常、手机 API、AI Prompt 和 Git 中都不得出现密码或完整连接字符串。
- 删除连接配置时同时删除对应 Windows 凭据；修改主机或用户名时不把旧密码写入 JSON。

### 6.2 账号与权限

- 允许配置现有账号，包括权限较高的账号；不因账号权限高低阻止连接、保存或只读查询。
- 仍推荐为 Assistant 创建只针对目标业务库的专用只读账号，作为数据库端的额外保护，但这不是产品功能的启用条件。
- “测试连接”可以读取并展示 `SHOW GRANTS FOR CURRENT_USER()` 的只读风险提示，但不得把高权限识别结果当作阻断条件。
- 数据库端权限是最后防线，本地 SQL 校验和只读事务不能替代最小权限账号。

### 6.3 查询执行护栏

- 连接驱动在实施阶段用官方文档验证 .NET 10、异步取消、TLS 和发布兼容性后选定；优先比较 Oracle Connector/NET 与 MySqlConnector，不在计划阶段锁死版本。
- 关闭多语句和本地文件导入，设置短连接超时、命令超时、连接池上限和连接生命周期。
- 只允许单条 `SELECT`、受限 `WITH ... SELECT`、Schema 元数据查询，以及明确允许的 `EXPLAIN`；拒绝写入、DDL、事务控制、存储过程、锁、文件、休眠和自定义危险函数。
- 服务端执行 `START TRANSACTION READ ONLY`，执行完成一律回滚或结束只读事务。MySQL 官方说明只读事务会阻止对普通可见表的修改，但临时表等仍有例外，因此它只能作为其中一层保护。
- 提示模型为明细 `SELECT` 显式添加 `LIMIT 50` 或更小；无论语句是否带 `LIMIT`，本地读取器都强制最多返回 50 行、64 KiB 结果、单字段 1,000 字符，并设置 5 秒查询超时，具体值做成有严格上限的高级设置。
- 二进制大字段不发送给 AI；列名疑似密码、密钥、token、身份证号等时默认掩码，并允许用户额外配置排除列。
- 数据库返回内容按“不可信数据”封装，防止数据字段中的文字被模型当作系统指令。
- 数据库目录缓存 15 分钟，内容稳定排序以利用模型前缀缓存；到期先复用旧快照并后台刷新，输入变化立即取消实时查询，连接切换或设置保存清空目录缓存。

数据库安全依据：

- [DeepSeek Tool Calls 官方指南](https://api-docs.deepseek.com/guides/tool_calls)
- [MySQL 8.0 `START TRANSACTION READ ONLY` 官方说明](https://dev.mysql.com/doc/refman/8.0/en/commit.html)
- [MySQL Connector/NET TLS 与连接选项](https://dev.mysql.com/doc/connector-net/en/connector-net-8-0-connection-options.html)
- [MySqlConnector 命令取消说明](https://mysqlconnector.net/overview/command-cancellation/)

## 7. 目标代码结构

保持历史命名空间 `NavicatTextProbe`，不做无收益的大规模改名。建议通过“抽离协调职责”降低 `MainWindow.xaml.cs` 的复杂度：

```text
MainWindow（只负责 WPF 绑定、按钮和生命周期）
│
├── AssistantCoordinator
│   ├── ContextCoordinator
│   │   ├── NavicatContextSource（复用现有 NavicatProbeService）
│   │   ├── WordContextSource（复用现有 WordDocumentContextService）
│   │   └── OcrContextSource（复用并扩展 VisionScreenshotCaptureService）
│   ├── SuggestionCoordinator（防抖、取消、上下文版本、候选）
│   ├── DatabaseContextCoordinator
│   ├── GuidedTypingCoordinator
│   └── OutputCoordinator（任务栏、手机、主窗口）
│
├── AssistantStateStore（单一只读快照 + 状态变更事件）
├── HotkeyRouter
├── DatabaseProfileService
├── DatabaseCredentialService
├── DatabaseSchemaService
├── SafeMySqlQueryService
└── GuidedTypingService
```

统一上下文快照至少包含：

- 来源类型、完整度和捕获方式；
- 前台进程、根窗口、文档身份；
- 正文哈希、正文长度、光标、选区；
- 数据库配置 ID、目录版本、工具调用序号；
- OCR 截图哈希；
- 单调递增的 `ContextVersion`。

所有 AI、数据库和 OCR 结果在落地前必须比对同一个 `ContextVersion` 及其必要字段。取消令牌用于尽快停止工作，上下文比对用于阻止无法及时取消的迟到结果，二者都必须存在。

交付闸门：现有 4096 截断、建表左括号、Word 题目、截图、任务栏和手机回归全部保持。

### 阶段 2：统一“智能分析”与 Word 文档授权

- 实现 `Ctrl+Alt+A` 的上下文路由：Navicat 选区诊断/强制续写、Word 识题或续写、失败提示 OCR。

交付闸门：密码不进 JSON/日志/手机/Prompt；无论账号权限如何，Assistant 都不会执行写语句；断网和超时不阻塞 UI。

### 阶段 4：AI 自主只读数据库工具

- 缓存账号可见的跨库目录，并把稳定目录提供给普通补全、候选和选区诊断。

- 实现 SQL 安全校验、只读执行、结果裁剪和敏感列掩码。

交付闸门：AI 无需特殊注释即可在必要时稳定查询；不需要实时事实时不轮询；写语句、批量语句、危险函数、超时和超量结果均被阻止；输入或光标变化立即取消。

## 10. 整体验收标准

1. Navicat 和 Word 的可靠全文、精确光标和来源状态可被统一表示；部分或不可信来源不会冒充全文。
2. 普通 Navicat 请求始终可参考缓存目录；AI 只有在需要实时事实或缺失精确 Schema 时才触发受限查询，不要求人工特殊注释。
3. 数据库建议能说明是否只使用目录、使用实时数据或发生降级，且数据库失败不拖死普通补全。
4. 密码不在源码、设置、日志、手机、AI 请求或 Git 中出现；即使配置高权限账号也不能通过 Assistant 执行写入。
5. 文档、光标、连接配置或截图变化后，旧请求和工具调用立即取消，迟到结果无法展示或代打。
6. 文本读取失败时不自动截屏；用户按 OCR 快捷键后可以获得当前屏幕答案。
7. 代打只输入 `InsertText`，每个合格物理按键推进一个文本元素；任何不确定情况自动停止并放行。
8. `Ctrl+Alt+M` 可以独立启停手机服务，手机继续展示完整答案且不暴露数据库敏感数据。
9. 三个状态灯与文字能准确表达主流程、数据库增强和代打状态。
10. `Ctrl+Alt+S` 关闭后只保留总开关热键，数据库、OCR、AI、代打、任务栏和手机全部停止。
11. 任务栏窗口继续保持无边框、不激活、不进 Alt+Tab、切换应用仍位于任务栏区域。
12. 全部现有回归自测、新增自测、Release 构建和发布流程通过。

## 11. 请用户拍板的决策项

以下是建议默认方案。用户确认整份计划即视为同意这些默认项，也可以逐项修改：

1. **数据库账号**：允许配置现有账号，不按账号权限高低阻止连接；Assistant 的执行通道仍必须强制只读，不能向数据库发送写入语句。（用户已明确修改并批准）
2. **数据库触发方式**：由 AI 根据缓存目录和当前 SQL 自主决定，用户无需写特殊注释；每次最多两次实时只读查询。（用户已明确修改并批准）
3. **Word 隐私策略**：自动本地读取全文，但每个 Word 文档首次发送 AI 前需要通过智能动作授权；切文档后重新授权。（建议：同意）
4. **OCR 范围**：快捷键默认截取当前光标所在显示器，不截取所有显示器；设置可切回仅前台窗口。（建议：同意）
5. **代打范围**：首版只支持 Navicat 和 Word；答案完成自动关闭；`Esc` 紧急退出。（建议：同意）
6. **核心快捷键**：采用 `S/A/O/D/M` 五个语义键；候选、选区诊断和 Word 识题按第 5 节合并或降为进阶交互。（建议：同意）
7. **数据库结果上限**：首版默认 50 行、64 KiB、5 秒，超过即裁剪或停止，不提供“无限制”选项。（建议：同意）
8. **实施策略**：在当前功能上分阶段抽离，不进行一次性重写；每阶段通过回归后再进入下一阶段。（建议：同意）
