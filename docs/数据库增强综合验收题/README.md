# Assistant 数据库增强综合验收题

这套题用于同时验证 Navicat SQL 补全、缓存数据库目录和 AI 自主只读查询。请只在个人测试服务器执行，不要把题目指向生产数据库。

## 使用顺序

1. 从托盘退出旧 Assistant，运行仓库根目录的 `run-probe.cmd`。
2. 在设置中确认数据库增强已开启、密码已保存、连接测试成功。
3. 用 Navicat 打开 `01-建库与综合操作.sql`，把光标依次放到每个 `TODO` 后面的空白行。先观察 Assistant 建议，再决定是否执行；不要一次执行整份文件。
4. 完成建库后，把设置中的“优先数据库”改成新建的测试库并保存，让 Assistant 立即刷新目录。
5. 完成造数后，新建一个独立查询页，只打开 `02-AI自主查询.sql`。不要把第一份脚本或种子数据复制过去，否则无法判断 AI 是否真的查询了数据库。
6. 每道题都先等待自动建议；需要三个方案时按 `Ctrl+Alt+R`。任务栏显示短建议，手机页查看完整 SQL 和说明。

## 观察重点

- 建表、常规联表和窗口函数只依赖当前 SQL 与缓存目录时，数据库状态应保持待命，不应反复查询。
- 第二份脚本中要求“实际 ID、实际城市、当前最低库存”等事实时，数据库状态应经历查询中并显示已使用实时数据。
- Assistant 可以给你生成 `CREATE`、`INSERT`、`UPDATE` 等待执行 SQL，但数据库工具本身只能执行只读查询；只有你在 Navicat 中主动执行 SQL 才会改变数据。
- 移动光标或继续输入后，旧的查询和建议不得迟到覆盖当前题目。

## 造数后的基础验收

完成 `01` 的种子数据、但尚未执行后续库存和订单更新时，应满足：

- `customers`：6 行；
- `products`：8 行；
- `orders`：13 行；
- `order_items`：22 行；
- `inventory_movements`：0 行；
- `paid` 订单：9 行；
- `pending` 订单：2 行。

这些数字只用于人工验收，不要复制到第二份 Navicat 查询页。
