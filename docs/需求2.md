# 需求 2：Word SQL 练习题 AI 识别与逐题作答

> 状态：P1 已完成；本文从“当前最终口径”开始的内容是 P2 唯一有效需求。此前“Word 自动随光标识题、本地按题号正则切题、`Ctrl+Alt+A` 再按一次退出固定”的方案均已废弃，不得恢复。

## 1. 背景与目标

Assistant 已能通过 Word COM 读取 `.doc`/`.docx` 主正文、精确光标和选区。P2 先实现一个垂直 MVP：辅助用户逐题完成 Word 中的 MySQL 8、SQL 和数据库原理练习题，包括选择题、填空题、简答题，以及带公共题干和多个小问的综合大题。

本功能的核心原则是：

- 用户通过 `Ctrl+Alt+A` 明确表示“我来到一道新题，请识别并切换到这里”，程序不再自动猜测用户正在做哪一题。
- 本地只负责可靠读取、截取上下文、标记光标、维护状态和验证返回值；题目边界、题型、题号、子问和作答状态交给 AI 理解。
- 一次 AI 请求同时完成当前题目定位和答案生成，避免先切题、再回答的两次调用。
- 顶层大题是唯一的题目切割单位。共享题干下的 `(1)`、`(2)`、`(3)` 等只是子问，不能切成三道独立题。

## 2. 产品范围

- Navicat 保持现有 MySQL SQL Copilot，不修改其捕获、补全、候选和诊断行为。
- Word 只支持 SQL/MySQL/数据库原理练习题。Word 未主动按快捷键时只展示正文、光标和选区读取结果，不自动向 AI 发送文档。
- 钉钉云文档当前仍只做读取预览，不接入 P2 AI 题目功能。
- WPS 暂不进入 P2 主链路。
- DeepSeek API Key 仍只存入 Windows 凭据管理器。

## 3. 用户主流程

### 3.1 进入或切换题目

1. 用户在 Word 中把文本插入光标放到准备作答的题干、选项、空格、SQL、子问或已有答案附近。
2. 用户按 `Ctrl+Alt+A`。
3. Assistant 立即捕获当前 Word 文档和光标，并提示“正在识别光标所在题目……”。
4. 首次请求发送光标前 300 个 UTF-16 字符和后 300 个 UTF-16 字符，并在精确位置放入唯一 `<CURSOR>`；同时携带当前选区（如有）和带编号的文本块。
5. AI 返回顶层题号、当前子问、题型、完整题目、作答状态、答案和解析。
6. Assistant 校验结果后保存为“当前题目”，任务栏显示 `题号.答案`，手机页显示完整题目、完整答案和解析。
7. 用户来到下一题时再次按 `Ctrl+Alt+A`。新结果直接替换旧题，不需要先退出固定状态，也不需要按两次。

`Ctrl+Alt+A` 的唯一含义是“识别并切换到光标所在题目”。在同一题再次按下时强制重新识别和刷新，不执行退出。退出或暂停整套 Assistant 仍使用 `Ctrl+Alt+S`；切换 Word 文档时清除旧题目，要求用户在新文档重新按 `Ctrl+Alt+A`。

### 3.2 题目激活后的行为

- 选择题和填空题：首次识别后直接显示答案；文档未变化时不持续重复请求。
- 简答题或综合大题：保存完整顶层题目。用户输入或移动光标后，经防抖重新发送当前题目和光标附近上下文，生成光标后的续写。
- 简答题的任务栏内容始终表示“光标后下一段应写什么”，不得把已检测到的用户答案或光标前文字当成新建议重复展示。
- 用户正按当前建议输入时，Assistant 在本地计算已输入前缀并立即只显示剩余后缀，不逐字请求 AI；当前建议全部写完后，再经防抖请求下一个缺失得分点。
- 用户正在选中或复制文字时暂停自动续写和在途请求，保留上一条有效建议；取消选区后再根据稳定的正文与光标决定是否更新。
- 用户移动到另一题但忘记按快捷键时，不自动切题。AI 判断当前光标不再属于已保存题目后，提示“当前仍是第 N 题；如已进入新题，请按 Ctrl+Alt+A”，不得再提示“请把光标移回该题”。
- 用户输入偏离当前建议后才生成新续写，避免任务栏闪烁。

## 4. 上下文窗口与自适应扩展

300 字前文和 300 字后文是首次请求的默认窗口，不是不可突破的硬上限。

1. 第一级：光标前后各 300 字。
2. 如果 AI 返回 `context_complete=false`、`needs_more_context`，或者题目范围触及窗口首尾，自动扩展为前后各 1,000 字并重试。
3. 仍不完整时扩展为前后各 3,000 字进行最后一次重试。
4. 三次都无法可靠定位时停止，不发送整份普通 Word 文档；提示用户把光标移到题干或选中完整题目后再按快捷键。

截取必须按原始 Word 文本坐标进行，并正确处理 `\r`、`\n`、Word 软换行 `\v`、表格单元格标记 `\a` 和其他正文控制字符。不能因为窗口裁剪移动 `<CURSOR>`。

为了保证题目原文准确，窗口按段落/软换行生成 `B001`、`B002` 等块编号。AI 返回起止块、边界锚点和 `question_text`；程序必须验证块编号顺序及锚点，并从请求中的原始文本重建完整题目。模型改写、缺字或虚构的 `question_text` 不能作为原文真值。

## 5. 大题与子问：提示词硬规则

以下规则必须直接写入系统提示词，并配有正反例：

1. 先寻找顶层题号和共享题干，再寻找子问。顶层题号常见形式包括 `4.`、`4、`、`第4题`、`简答 4.`、`综合题四` 等；格式只是线索，语义层级优先。
2. 如果一段说明、表结构、业务背景、SQL、数据样例或公共条件后出现 `(1)`、`(2)`、`(3)`，这些编号是同一道顶层大题的子问。
3. 完整题目必须包含顶层题号、公共题干、SQL/表结构/数据，以及所有属于该题的子问，直到下一道同级顶层题或答案解析章节为止。
4. 绝不能因为光标位于 `(2)`，就只返回 `(2)` 或把 `(2)` 当作顶层题号。
5. 返回 `question_number` 时使用顶层题号；`active_subquestion_number` 单独返回当前子问，例如 `question_number="4"`、`active_subquestion_number="2"`。
6. 首次答案要覆盖整道大题的全部子问，并保留 `(1)`、`(2)`、`(3)` 结构。续写时只续写光标当前所在的答案或子问，不重复其他已经写出的部分。
7. 只有文档确实从头到尾使用 `(1)`、`(2)` 作为同级题号，且不存在共享的上级题干时，才能把它们识别成独立顶层题。

正例：

```text
简答 4.（10 分）
给定查询：
SELECT * FROM orders ...
(1) 设计联合索引。
(2) 说明列顺序理由。
(3) 举出两种索引失效写法。
```

无论光标位于 SQL、`(1)`、`(2)`、`(3)` 或其答案中，都必须返回一份包含公共 SQL 和三个子问的“第 4 题”；当前子问另行标记。

反例：返回 `question_number="(2)"`，或只把“说明列顺序理由”作为完整题目，均属于不可接受结果。

## 6. 作答状态与简答续写

AI 必须区分：

- `empty`：用户尚未作答。`full_answer` 和 `insert_text` 均可给出完整答案。
- `partial`：用户已写一部分。`insert_text` 只能给 `<CURSOR>` 后应继续输入的文字，不能重复光标前内容。
- `complete`：答案已经基本完整。优先返回缺失得分点、纠错或精炼内容；没有必要补充时允许 `insert_text` 为空。
- `uncertain`：无法可靠区分题干与用户答案。说明原因，不得强行重复整份答案作为续写。

用户按快捷键时保存一份文档基线。后续请求除已保存的完整题目外，还发送：

- 当前光标前后各 300 字；
- 精确 `<CURSOR>`；
- 当前选区；
- 相对基线能够可靠识别的新增或修改内容；
- 上一条建议；如果用户仍在跟随该建议，则由本地直接抑制本次请求。

即使用户在按快捷键前已经写过答案，AI 仍需从上下文识别已有作答。如果光标位于已有答案中间，还必须参考光标后的文字，不能生成与后文重复或冲突的内容。

对于 `partial`，`display_text` 只能概括或预览 `insert_text` 所代表的下一段内容，禁止复述 `detected_user_answer`、光标前文字或用户已经写出的答案。任务栏以 `insert_text` 为续写真值；即使模型违反该规则并在 `display_text` 中复述旧答案，程序也必须优先显示 `insert_text`。

## 7. AI 请求与返回协议

请求模式：

- `locate_and_answer`：按快捷键后定位/切换题目并给出首次答案。
- `continue_current_question`：题目已保存后，根据已有作答和当前光标续写。

模型只返回合法 JSON：

```json
{
  "mode": "exercise_answer",
  "is_question": true,
  "context_complete": true,
  "needs_more_context": "none",
  "same_as_current_question": true,
  "question_number": "4",
  "active_subquestion_number": "2",
  "question_type": "short_answer",
  "question_start_block_id": "B003",
  "question_end_block_id": "B010",
  "question_start_anchor": "简答 4.（10 分）",
  "question_end_anchor": "(3) 另举两种会导致该索引失效的写法。",
  "question_text": "完整题目原文",
  "answer_state": "partial",
  "detected_user_answer": "用户已有作答",
  "display_text": "光标后下一步文字的短预览，不含顶层题号",
  "insert_text": "仅从光标后继续输入的内容",
  "full_answer": "完整参考答案",
  "explanation": "详细解析",
  "issues": [],
  "confidence": 0.95
}
```

允许值：

- `mode`：`exercise_answer`、`exercise_continuation`、`not_exercise`。
- `needs_more_context`：`none`、`before`、`after`、`both`。
- `question_type`：`choice`、`fill_blank`、`short_answer`、`unknown`。
- `answer_state`：`empty`、`partial`、`complete`、`uncertain`。

程序必须拒绝以下结果：非法块编号、起止倒置、题目锚点不存在、定位结果完全不接近光标、`is_question=false` 却返回答案、置信度低于最低阈值，或返回结果对应的文档哈希/光标已经过期。

## 8. 答案格式与输出渠道

顶层题号和答案由程序拼接，不能依赖模型自己遵守标点：

```text
1.B（DDL）
2.DECIMAL(10,2)
4.(1) INDEX(user_id, status, created_at)；(2) 等值条件列在前……
```

- 模型的 `display_text`、`insert_text` 和 `full_answer` 不得重复顶层题号。
- 简答题为 `partial` 或续写模式且 `insert_text` 非空时，任务栏答案主体必须来自 `insert_text`；`detected_user_answer` 只用于判断作答状态和手机页详情，不能作为任务栏建议。
- 程序规范化 `第4题`、`4.`、`4、` 为题号主体 `4`，再输出 `4.答案`。
- 无法可靠识别题号时使用 `当前题.答案`，不得编造题号。
- 任务栏显示题型、`题号.答案`，总长度不超过 100 字符；长答案截断但不影响手机页。
- 手机页显示题号、当前子问、完整题目、完整答案、当前续写和解析。

## 9. 请求调度与正确性保护

第一版不实现持久化答案缓存，每次新的有效上下文均可请求 AI；但以下保护属于正确性要求，不能删除：

- 相同文档哈希、光标、请求模式和当前题目不重复请求。
- 保留防抖和最小请求间隔。
- 新输入、切题、切换文档或关闭 Assistant 时取消旧请求。
- AI 返回后再次验证文档身份、哈希、光标和当前题目标识，迟到结果不得覆盖新题。
- 用户输入仍在跟随当前建议时不重新请求。
- 跟随建议输入期间，本地持续展示尚未输入的后缀；完全输入后允许请求下一个缺失得分点。退格仍按原建议重新计算剩余后缀，偏离建议才取消本地跟随并请求 AI。
- Word 存在非空选区时暂停自动请求并取消在途续写，避免选择、复制和选区端点变化制造无效请求；选区折叠后自动恢复判断。
- 请求失败时保留上一条有效答案，并在详细信息中提示失败原因，不能让任务栏在答案和错误之间闪烁。
- 日志记录请求模式、窗口范围、扩展级别、题号、子问、题型、作答状态、耗时、输入/输出 token 和缓存命中 token；不得无必要输出完整题目或用户答案。

## 10. 用户可见状态与异常体验

- Word 未按快捷键：显示当前软件、光标内容和选区；提示“按 Ctrl+Alt+A 识别当前题目”。
- 正在识别：`正在识别光标所在题目……`
- 扩展上下文：`题目可能超出当前窗口，正在扩大范围……`
- 已识别：`当前题目：第 N 题（简答题），Ctrl+Alt+A 切换新题`
- 当前光标似乎离开题目：`当前仍是第 N 题；如已进入新题，请按 Ctrl+Alt+A`
- 新文档：清除旧题，显示 `已切换 Word 文档，请按 Ctrl+Alt+A 识别题目`
- 上下文仍不足：`未完整识别题目，请把光标移到题干或选中完整题目后重试`
- 非 SQL 数据库练习题：不回答，显示 `当前内容不像 SQL 数据库练习题`
- API Key 缺失或 AI 关闭：不改变当前题目状态，给出明确设置提示。

- Navicat SQL Copilot 全链路。
- DeepSeek JSON Output、非思考模式、API Key 管理。

- 任务栏、手机页、总开关及热键配置能力。

## 12. 用户场景与验收标准

至少覆盖以下回归：

1. `**1.**` Markdown 题号和分行 A/B/C/D 选项，光标在任一选项都能返回 `1.答案`。
2. Word 自动编号不出现在 `Range.Text` 时，AI 仍可根据上下文识别；不能可靠取得题号时使用“当前题”。
3. 大题包含公共 SQL 和 `(1)(2)(3)`，光标在任一子问或答案中都返回同一个顶层题号和完整大题。
4. 文档只使用 `(1)(2)` 作为同级题号且没有公共上级题干时，识别为两道独立题。
5. 简答题未作答时给完整答案；已有半句时只续写后半部分；光标位于答案中间时不重复后文。
6. 用户在 `(1)` 写完后移动到同一大题的 `(2)`，继续针对同一个顶层大题，不出现“请把光标移回该题”。
7. 用户移动到下一题但忘记按快捷键，不自动切换，提示重新按 `Ctrl+Alt+A`。
8. 题目超过 600 字时触发 1,000/3,000 字自适应扩展；扩展仍失败时不误答。
9. “参考答案与评分要点”位于窗口中时，模型可将其作为参考，但不能把答案章节当成用户作答或当前题目。
10. AI 返回错误块编号、过期文档结果或低置信度时被拒绝，上一条有效答案不被覆盖。
11. 连续快速输入只保留最新请求；跟随建议输入不闪烁、不重复请求。
12. 切换 Word 文档、关闭总开关或退出程序时，题目状态和在途请求正确清理。
13. 简答题已经写有 `1NF... 2FN:` 等部分答案时，任务栏显示 `2FN:` 后尚未写出的内容，不得原样复述已有答案；继续照写时提示在本地逐步缩短。
14. 选择或复制 Word 文字期间不触发自动续写，取消选区后恢复，且上一条有效答案不丢失。

最低交付标准：`git diff --check`、Release 构建 0 警告 0 错误、全部自测通过、发布到 `dist/Assistant`，并在真实 Word 文档中验证选择题、填空题、普通简答题和带多个子问的综合大题。
